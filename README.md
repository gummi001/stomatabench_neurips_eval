# StomataBench: Measuring Taxonomic Generalization in Stomatal Detection

Sainath Reddy Gummi, Hankui K. Zhang, Chulwoo Pack, Shyam Solanki, Young Chang

Evaluation code and result tables of the paper. Everything from the detectors' predictions to the tables and figures is regenerated by the scripts here.

## Repository layout

```
inference/        infer_*.py: run one fine-tuned detector over one set and write COCO-format predictions
configs/          the RT-DETRv4 config used with the official RT-DETRv4 code
evaluation/       one script per evaluation step (see below); common.py holds the shared constants
figures/          scripts that draw the figures of the paper from the result tables
scripts/          download.py, run_inference_*.sh, run_eval.sh, run_figures.sh
results/          the result tables the paper was built from (CSV)
tests/            compare_outputs.py: compare a fresh run with results/
```

## Reproduce the results

The evaluation needs no GPU and no images: it reads the released predictions, the COCO annotations and the master metadata CSV.

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python scripts/download.py eval      # coco.json files, metadata CSV, predictions -> data/StomataBench/
bash scripts/run_eval.sh             # writes outputs/
python tests/compare_outputs.py outputs results
bash scripts/run_figures.sh          # writes outputs/figures/
```

On Windows, run the `.sh` scripts from Git Bash or WSL. `compare_outputs.py` reads every CSV in `results/` and checks that the fresh run in `outputs/` has the same rows and columns and the same values (to a relative tolerance of 1e-9). The bootstraps use fixed seeds, so their intervals are reproduced exactly.

`run_eval.sh` runs these steps in order:

| Step | Script | Output folder | What it computes |
|---|---|---|---|
| 1 | `select_thresholds.py` | `thresholds/` | Per-model confidence thresholds and one shared threshold, selected on OD-Valid (species-balanced count MAE) |
| 2 | `evaluate_coco.py` | `coco/` | COCO AP50:95, AP50, AP75, AR@100 per set and per species, all boxes (no confidence filter), maxDets 100 |
| 3 | `evaluate_count_density.py` | `count_density/` | Count and density MAE, signed bias, R2 per image, species and set, under six confidence settings |
| 4 | `evaluate_detection.py` | `detection/` | TP, FP (duplicate, localization, background), FN, precision, recall, F1 at IoU 0.30 and 0.50 |
| 5 | `bootstrap_count_density.py` | `bootstrap/` | Paired image bootstrap intervals of count and density MAE and R2 at the fixed 0.25 threshold |
| 6 | `threshold_uncertainty.py` | `threshold_uncertainty/` | Bootstrap and leave-one-species-out uncertainty of the selected thresholds |
| 7 | `bootstrap_example_species.py` | `example_species/` | Point values and intervals for the example species of Table S21 |
| 8 | `bootstrap_example_ap.py` | `example_ap/` | COCO AP with intervals for the example species and models of Table S21 |
| 9 | `analyze_threshold_ap.py` | `threshold_ap/` | Per species: does the best model change between thresholds, and does the AP leader also lead counts |
| 10 | `analyze_wheat.py` | `wheat/` | Density errors and detections on the calibrated Gibbs wheat images of T-GSH |
| 11 | `build_result_tables.py` | `tables/` | The result tables of the paper as CSV, and one per-image file with every count |

The six confidence settings are the full released score range, fixed thresholds 0.25 (primary), 0.50 and 0.75, one shared threshold and one threshold per model, both selected on OD-Valid and frozen before the test sets are scored. Results are reported on all images and on scene-primary images (one image per field of view, `is_scene_primary` in the metadata CSV); the paper uses scene-primary images. Density is computed only for images with a physical scale (`has_density`).

## Columns of the result tables

Most files are long tables, one row per set, model, image view, group and confidence setting.

| Column | Values |
|---|---|
| `dataset` | `OD-Valid`, `T-MAWP`, `T-DCWP`, `T-MSWP`, `T-GSH` |
| `model` | one of the 15 detectors, named as the folders of the weights repository |
| `image_scope` | `all` images or `scene_primary` images (in `coco/`: column `subset`, values `all` and `dedup`) |
| `group_level` | `dataset` (the whole set, pooled), `species`, or `species_acquisition` (species by source and calibration group) |
| `confidence_protocol`, `threshold` | `Available support` (every released box), `Shared`, `Model-specific`, or `Fixed` with its threshold |
| `matching_iou` | IoU used to match boxes to stomata (detection tables) |
| `count_*`, `density_*` | `_n` images, `_mae`, `_signed_bias` (prediction minus truth), `_r2` (1 − SSE/SST about the observed mean), `_pearson_r`; density in stomata per mm² |
| `macro_species_*` | the species values summarized with equal weight per species (R2 only for species with at least three images) |
| `AP50_95`, `AP50`, `AP75`, `AR100`, ... | COCO metrics in percent |
| `small_n_flag`, `small_n_count_flag`, `small_n_density_flag` | `descriptive_only_n_lt_5` when a group has fewer than five images |

`tables/per_image_measurements.csv.gz` has one row per image and model with the ground-truth count and density and the number of boxes kept under each confidence setting (`available_support`, `shared_0p254`, `model_specific`, `fixed_0p25`, `fixed_0p50`, `fixed_0p75`).

## Re-run the detectors

The predictions in the dataset repository were made with the scripts in `inference/`. To make them again you need a CUDA GPU, the images and the weights:

```bash
python scripts/download.py images    # images of the five evaluation sets, coco.json files, metadata CSV
python scripts/download.py weights   # the 15 checkpoints -> data/weights/
bash scripts/run_inference_detectron2.sh   # FRCNN-*, Retina-*
bash scripts/run_inference_yolo.sh         # YOLOv8, YOLOv11, YOLOv12, YOLOv26
bash scripts/run_inference_hf.sh           # RT-DETRv2, GDINO-SB
bash scripts/run_inference_rtdetrv4.sh     # RT-DETRv4
bash scripts/run_inference_sam3.sh         # SAM3-OD
```

New predictions go to `outputs/predictions/` and never overwrite the downloaded ones. Evaluate them with `PRED=outputs/predictions bash scripts/run_eval.sh`. Each framework needs its own environment:

| Script | Framework | Also needs |
|---|---|---|
| `run_inference_detectron2.sh` | [Detectron2](https://github.com/facebookresearch/detectron2) | |
| `run_inference_yolo.sh` | [Ultralytics](https://github.com/ultralytics/ultralytics) | |
| `run_inference_hf.sh` | [HuggingFace Transformers](https://github.com/huggingface/transformers) (the checkpoints record version 4.53.3) | the `IDEA-Research/grounding-dino-base` processor, downloaded from the Hub |
| `run_inference_rtdetrv4.sh` | [RT-DETRv4](https://github.com/RT-DETRs/RT-DETRv4) at commit `df44122` | `RTDETRV4_REPO` set to that clone, with `configs/rtv4_hgnetv2_l_stomata.yml` and `configs/stomata_detection.yml` copied to its `configs/stomata/` |
| `run_inference_sam3.sh` | [SAM 3](https://github.com/facebookresearch/sam3) | `SAM3_BASE_WEIGHTS` (the official `sam3.pt`) and `SAM3_BPE_PATH` (`assets/bpe_simple_vocab_16e6.txt.gz` of the SAM 3 code) |

Every prediction file has a `<set>_meta.json` next to it in the dataset repository, with the settings, checkpoint hash, GPU and PyTorch version of the run that made it.

`configs/` holds the RT-DETRv4 config of the paper, unchanged. Its output, DINOv3 and training-data paths are those of our cluster. Inference reads only the model part of the config, so these paths matter only for training.
